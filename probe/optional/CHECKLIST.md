# Confluence DC probe — 실행 절차와 보고표

목적: 사내 Confluence에서 **실제로 무엇이 렌더링되는가**를 확정한다.
이 결과가 `confluence-post` 스킬 규칙의 유일한 근거가 된다. 추측으로 채우지 않는다.

## 0. 먼저 적을 것 (스킬 규칙이 여기서 갈린다)

| 항목 | 확인 위치 | 값 |
|---|---|---|
| Confluence 버전 | 도움말(?) > About Confluence, 또는 페이지 하단 | |
| Insert(+) > Markup 메뉴 존재 | 편집 화면 상단 + 버튼 | |
| Markup 대화상자의 선택지 | Confluence Wiki / Markdown 둘 다 있는가 | |
| Code Block macro 언어 드롭다운 | 매크로 삽입 > Code Block > Language | |
| PAT 발급 가능 | 프로필 > Personal Access Tokens 메뉴 유무 | |
| 내 space key / 초안 부모 페이지 | | |

Code Block 언어 목록은 **드롭다운을 열어 전부 그대로 옮겨 적는다.** 여기 `c`가 있는지,
`rust`/`go`/`json`/`markdown`이 있는지가 커널 문서에서 매번 걸린다.

## 1. 실행

1. 개인 space에 빈 페이지를 만든다. 제목은 `Confluence DC 문법 probe (wiki markup)`
   — P18의 내부 페이지 링크 테스트가 이 제목을 참조한다.
2. 편집 화면 > Insert(+) > Markup > **Confluence Wiki** 선택.
3. `PROBE-wiki.txt` 전체를 붙여넣고 Insert. 한 번에 안 들어가면 `h2. P13`을 기준으로 반씩 나눈다.
4. 저장하고 **읽기 화면**을 본다 (편집 화면이 아니라 저장된 화면 기준으로 판정).
5. 화면 캡처를 위에서 아래로 찍는다. 항목마다 `P01`~`P26` 제목이 붙어 있어 캡처만으로 판독된다.
6. 새 페이지를 하나 더 만들어 Insert > Markup > **Markdown**으로 `PROBE-markdown.md`를 넣는다.
   Markdown 선택지가 없으면 그 사실만 적고 건너뛴다.

## 3. 결과가 결정하는 것

- P02가 "줄바꿈"이면 → 변환기가 md 문단을 한 줄로 합쳐야 한다.
- P08/P09가 X면 → 표 열 수 상한과 "표 안에 커맨드 금지" 규칙이 생긴다.
- P11에서 `c`가 없으면 → C 코드는 `cpp`로 매핑하는 규칙을 스킬에 박는다.
- P21에서 아무것도 없으면 → 도식은 noformat ASCII 또는 이미지 첨부뿐이다.
- M06 표가 되면 → md를 그대로 넘기는 경로가 살아난다. 안 되면 wiki markup 변환이 유일한 길이다.
